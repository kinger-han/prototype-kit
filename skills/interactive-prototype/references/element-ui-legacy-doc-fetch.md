# Element UI 老系统规范核查 / UI 交接

## 触发场景
原型按 AntD5 设计，但用户告知"前端实际用 Element UI（老系统风格）"。判断哪些页面需要重新 UI 设计、给 UI/前端开发出交接文档前，必须**真实核查 Element UI 组件能力**，不能凭记忆/想当然。

## 用户偏好（2026-08-21 明确）
- 用户原话："不能自以为，想当然"、"要根据实际的网址里面的内容来"。判断 UI 能力、工作量、是否可跳过 UI 设计时，**必须基于官方文档/真实截图**核实，不臆断组件能力。
- 原型配色参考偏好是 AntD5 蓝（#1677ff/#e6f4ff），但**落地实现基准是 Element UI + 现网系统风格**，两者要区分——给 UI 出交接单时默认按 Element 老系统风格对齐，除非用户说按 AntD。

## 关键技术：Element UI 官网超时的替代抓取
`https://element.eleme.cn/#/zh-CN/component/xxx` 是 hash 路由 + 重渲染 SPA：
- `browser_navigate` 常超时（timeout 或 element not exist）——官网加载不动，**不要反复重试**。
- **可靠替代**：从 GitHub 抓官方 Markdown 文档源（最权威、纯文本）：
```bash
curl -sL --max-time 25 "https://raw.githubusercontent.com/ElemeFE/element/dev/examples/docs/zh-CN/<组件名>.md" -o /tmp/elemdoc.md
# 组件名：dialog / tree / drawer / cascader / select / transfer / table ...
```
同一站点只抓一次即可，多控件循环依次抓。已实测可用（2026-08-21）。

## Element UI 老系统组件能力速查（实测自官方文档，供判断"是否可跳过UI"）
| 控件 | 能力 | 对应资源管理场景 |
|------|------|------|
| Dialog | 基本/自定义内容/嵌套/居中/全屏/footer 插槽 | 各类操作弹窗全部可承载 |
| Tree | **show-checkbox 多选**、节点自定义（选中后操作按钮）、node-key 唯一、highlight-current 高亮 | 标签/类别**多级筛选弹窗**、左树 |
| Cascader | **多选、可搜索、动态加载(lazy)、仅显示最后一级、任意层级** | 三级类别筛选（老系统可能用它替代弹窗树） |
| Drawer | 方向(rtl/ltr/ttb/btt)/size/嵌套/自定义内容(可嵌表格表单)/with-header、append-to-body | 审核**主题抽屉**（路径+统计+资源列表）完整承载 |

**核心判断**：弹窗、多级树筛选、级联、抽屉，Element 老系统全部原生支持 → **这些大多不需要 UI 重新设计**，前端直接套 Element 组件落地即可。真正缺专属视觉、必须 UI 的是：资源卡片网格、统计卡大盘、主题/资源视图切换、拖动排序、横竖版详情/编辑布局。

## 判断"哪些页面可跳过 UI 设计"的复用框架
- **可直接开发/跳过 UI**：页面元素 100% 为标准组件（表格/表单/弹窗/树/级联/抽屉）+ 老系统已有同类页（如审核列表页直接照抄现网同类）。UI 只出 1 页样例即可。
- **必须 UI**：含 Element 组件库没有的专属视觉资产（卡片网格、统计大屏、视图切换、拖拽、横竖版尺寸适配）。
- 工作量大小时，先确认"弹窗/树/抽屉是否现成"——现成则弹窗类改造不耗 UI，重头只在专属视觉那几个点。

## 用户当前项目（主题管理V2）
前端技术栈 Element UI，系统老风格：深蓝侧边栏 + 白内容区 + 面包屑 + 幽灵筛选/导出/下载按钮 + 斑马纹表格 + "共N条"分页 + 状态标签(绿/橙/红)。详情/编辑页横竖版资源尺寸不一易留白/布局乱，是必须 UI 设计的专项。详见 memory「主题管理-前端技术栈」。
