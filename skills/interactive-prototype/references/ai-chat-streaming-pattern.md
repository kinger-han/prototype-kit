# AI 问答页：流式输出 + 结构化回答卡

> 触发：原型里要做 AI 问答 / 搜索问答页，或任何「AI 正在生成」的界面。
> 两处已落地的参考实现（**先 grep 定位再局部读，不要整文件读**）：
> - AI校史馆：`AI校史馆/prototype/pages/mobile/03-chat.html`（回答引擎 + 渲染）＋同项目 `shell-mobile.html` 里 `/* S02 对话页 */` 那一段 CSS
> - 智能导游：`智能导游/prototype/dist/智能导游-小程序.html`（打字机光标 + 引导追问）
> 常用定位锚点：`grep -n "ai-card\|ai-cursor\|runAnswer\|stepStream\|msg-bubble"`

## 1. 为什么不能只做一个白气泡

用户对 AI 问答页「高级还是业余」的判断几乎全在**回答的结构**上，不在气泡圆角。成熟产品（豆包 / Kimi / 元宝）的做法是：**回答 = 一张整宽卡片，内部按层组织**，而不是一个放大的聊天气泡。

卡片内固定六层：

| 层 | 作用 | 缺了会怎样 |
|---|---|---|
| 标题（结论句） | 一眼知道答了什么 | 用户得读完整段 |
| 正文（分段 + 关键数据加粗） | 主体 | 视觉上是一坨 |
| **来源条** | 可信度（党建 / 政务场景的核心卖点） | 和通用大模型没区别 |
| 延伸内容（海报 / 卡片） | 承接自己的内容库 | 回答孤零零 |
| 继续问（追问 chips） | 给出下一步动作 | 用户不知道还能问什么 |
| 操作条 | 复制 / 朗读 / 重答 / 赞踩 | 没法反馈 |

- 追问用**胶囊 chips**（宽度随文案、可换行或横滑），**不要通栏大按钮**——三个通栏按钮能吃掉一整屏，把操作条挤出屏幕。
- 操作条：左侧「操作」（图标 + 文字），右侧「评价」（纯图标），靠分组间距区分；文案别长到换行（「重新回答」→「重答」），加 `white-space:nowrap`。
- 来源条要**看得出可点**：右侧给一个实体小按钮（「查看原文」），不要只靠下划线暗示。

## 2. 状态机（三态起步）

```
retrieving  → 转圈 + 「正在查找XX资料…」     ← 必须停留 600~700ms 再进下一步
generating  → 标题先出，正文逐字 + 闪烁光标 + 「停止生成」
completed   → 展开来源 / 延伸 / 追问 / 操作条
   ├─ stopped       用户点了停止（保留已生成部分 + 「已停止生成」）
   ├─ failed        重试按钮
   └─ no_evidence   查不到就说查不到 + 换问法 / 提交线索
```

- **检索态不能省**：先让用户看到「在查资料」比直接蹦字可信得多——产品卖点若是「答案来自权威文件」，检索过程本身就是价值展示。
- **后端契约映射**（AI校史馆的做法，值得保留）：按 `answerType` 分支渲染不同卡面（`grounded_answer` / `no_evidence` / `safety_reply` / `off_topic`）。「查不到」必须有独立卡面，不能让模型硬编。

## 3. 逐字渲染：不要切坏 HTML 标签

朴素做法 `text.slice(0, n)` 会把 `<b>` 切一半 → 半截标签当字面量显示。**用标记符代替标签，切片之后再转换**：

```js
// 数据里写标记：'对党员的纪律处分共〖五种〗'
function fmt(t){
  // 未闭合的标记整体丢弃（光标正停在标记中间时）
  var o = (t.match(/〖/g)||[]).length, c = (t.match(/〗/g)||[]).length;
  if (o > c) t = t.slice(0, t.lastIndexOf('〖'));
  return t.split('\n\n').map(function(p){
    return '<p>' + p.replace(/〖([^〗]*)〗/g,'<b>$1</b>').replace(/\n/g,'<br>') + '</p>';
  }).join('');
}
```

节奏参考：正文 >160 字时每 tick +4 字、`setTimeout(…, 32)`；短文 +2 字。

## 4. 性能与滚动

- **流式时只重绘正文节点**（`document.getElementById('streamText').innerHTML = …`），不要整卡 `innerHTML` 重渲染——否则每 tick 都触发一次入场动画、滚动乱跳、光标闪断。
- 滚动跟随：默认自动滚到底，但**用户手动上滚后停止自动滚**，并显示「回到最新」浮动按钮（判据 `scrollHeight - scrollTop - clientHeight < 46`）。
- 消息入场用一次性 `@keyframes`（`opacity` + `translateY(7px)`），不要用 transition 反复触发。

## 5. 演示用的两个小开关

- **首屏自动播一段**：首次进入该页时 `setTimeout(function(){ ask('示例问题'); }, 700)`，打开就能看到流式效果，演示时不用现场打字。用 `chatInited` 标记保证只播一次。
- **输入框真输入**：`input` 事件控制发送按钮两态（空 = 灰、有内容 = 主色 + 投影），回车发送；按关键词匹配预设答案（`q.indexOf('党费') > -1`），匹配不到给通用回答——被随便问一句也不尴尬。

## 6. 内容一致性（交付前必查）

回答里引用的图 / 卡片必须与问题同主题，且**答案要能从图上直接读出来**（海报印着「雷锋 1940—1962」，题就问享年）。图文不符是评审第一眼就能抓到的问题；详见 SKILL.md「演示数据与交付」同名条目。

## 7. 弹层闭环

- 来源条点开 → 弹层显示引文原文 + 「打开原文」外链（给权威源白名单域名）。
- 延伸海报点开 → 弹层展示大图 + 「就这张问 AI」，形成闭环。
- **每张图必须绑到自己的弹层 key**：`posters: [{ i:'poster-3.png', t:'图解条例', s:'poster3' }]`，不要所有图共用同一个预览弹层——点了哪张都显示同一张，是静默 bug，肉眼验收时才发现不了。
