# 同底片衍生作品（风格化/多版本）合并展示模式

> 来源：党代会 AI 纪念相册 V2.1 风格化落地（2026-09-07，方案1 = 标签合并展示）。
> 适用：任何"同一底片/同一对象生成多个版本（画风、滤镜、多副本）"的功能设计。完整交接见项目内 `docs/风格化功能V2.1页面改动交接说明.md`（V2.2 实际落地版）。

## 1. 方案判据：合并展示 vs 独立详情页

用户问"方案1（原图详情页内标签切换 + 我的纪念合并卡）vs 方案2（每个风格独立详情页）哪个好"。结论：**方案1**。判据可复用：

| 维度 | 合并展示（标签切换） | 独立详情页 |
|---|---|---|
| 用户心智 | 风格是"这一张照片"的变体（同模板/同底片/同人）→ 一个对象多视图 | 每个风格像独立纪念作品 → "第 N 号档案"被同一张脸拆成 N 个，参与感稀释 |
| 核心场景 | 风格化本质是"对比选择"（原图↔风格秒切，人脸一致性一眼能比） | 逐页跳转对比，成本高 |
| 开发成本 | 无新路由/新页面，改动收敛在详情页 + 列表页 | 新路由 + 新详情页 + 未定案入口 |
| 数据模型 | 后端 `sourceWorkId` 归组天然对齐 | 前端不合并展开时 H10 变成一堆重复同脸卡片 |
| 合规 | 同页秒切 → 人脸一致性/风格合规对比成本最低 | 分散 |

**例外**：当每个变体都要作为完全独立的正式作品被高频独立传播/管理时才考虑拆页。

## 2. 数据模型

- 派生作品（Style/多版本）加两字段：
  - `sourceWorkId`：指向来源原图/主作品；空 = 主作品本身（直出）。
  - `styleId`：画风/版本 ID；空 = 直出。
- 归组（group）= 主作品 + 全部 `sourceWorkId === 主作品.no` 的派生。
- 派生编号 = 全局流水号顺延（如 `FJDH-0328-05`），**仅后台主键**；界面不显示派生流水号，显示 `水墨国风 · 源自 FJDH-0328-01`。
- 全局画风列表用 `window.__STYLE_LIST`（PC）/ `var STYLES`（移动端 mock），含 id/name/time/enabled/prompt/count。

## 3. 原型落地结构

### 移动端详情页（08-result）
```
大图（当前标签那张，3:4，带画风滤镜类 effect-<styleId>）
├─ 标签行 .r-tabs： [原图] [水墨国风] (+ 加个风格)
│    · 已生成平铺；默认选中进入时的作品（state.curWork.no 定位）
│    · 生成中的画风显示转圈占位；完成带"新"红点
│    · 末尾 "+ 加个风格" 弹层只列未生成且 enabled 的画风；全关/全生成 → 入口隐藏
├─ 作品信息：主作品显示"第 N 号档案 · 编号"；派生显示"风格名 · 源自 主编号"
├─ 操作区 .ra-actions：两个并列主按钮 [保存本地] [分享上屏]（作用于当前标签）
└─ 分享说明区（仅未提交时显示）
```
- 关键函数：`loadResultGroup()`（按 curWork 归组 + 设 curTabIdx）、`renderTabs()`、`switchTab(i)`、`applyTab()`（切大图/编号/状态）、`startStyleGen(styleId)`（setTimeout 3s 模拟生成 → push 派生作品 → 重拉组选中新风格）。
- 切标签时重置 `state.sbChecked`（勾选授权不跨标签共享）。

### 移动端我的纪念（10-mine）
- `_mineGroups()` 按 sourceWorkId 归组；卡片 = 主作品大封面 + 派生缩略行 `[原图][水墨国风]` + 右下 `✦N` 角标（N=组内总数，不折叠）。
- 点主卡/原图缩略 → 打开主作品详情（默认原图标签）；点派生缩略（`event.stopPropagation()`）→ 详情默认选中该风格标签。
- 风格缩略带滤镜 + 展示中绿点；无派生卡片与现状完全一致。

### PC 详情弹窗（shell-pc，共用）
- `pdBuildGroup(no)` 按 `sourceWorkId` 归组 → `__pdGroup[]` + `__pdTab`；`pdRender()` 渲染标签行与字段。
- **公共字段固定（不随标签）**：模板 / 微信号 / 来源屏幕；**作品字段随标签**：画风 / 上屏状态 / 创建时间 / 上屏展示时间 / 下屏时间；派生额外一行 `源自 <主编号>`。
- 大图放大（pdZoomPhoto）跟随当前标签。

### PC 管理新页（画风管理）
- 字段：示例（滤镜缩略图）/ 画风名称 / 预计耗时 / 生成数量 / 提示词（长文本列）/ 状态 / 操作（编辑 + 启用|禁用）。
- 编辑弹窗：名称 / 预计耗时 / 状态 / 生成数量 / 提示词 textarea。
- 数据源 = `window.__STYLE_LIST`，与详情弹窗画风名共用；用户说"生成数量什么的你看着来"= 展示字段保持精简即可。

## 4. 踩坑（本模式特有）

1. **跨页共享详情数据被覆盖**：照片管理 `buildPhotoDetails()` 与上屏审核 `selBuildDetails()` 写同一个 `window.__PHOTO_DETAILS` → 切页后打开详情读到另一页残留 map（衍生标签数量不一致）。修法：每次打开详情前**无条件重建自己的数据**，不要只在为空时构建。
2. **全局列表多脚本兜底初始化**：多个页面脚本都可能先执行（build 注入顺序不确定）→ 兜底用 `window.X = window.X || [...]`；后执行页直接赋值会覆盖前页完整数据。
3. **PC 缩略背景类可能不存在**：PC 端 `wb-*` 背景类未必有全局定义（移动端才有）——PC 新页缩略图自给固色/渐变，不依赖 wb-N。
4. **"更多风格"常驻区块被用户砍掉**：非必要不保留常驻大片区，折叠进标签行 `+ 加个风格` 轻量弹层（用户明确："这非必要不保留，要考虑用户的交互"）。

## 5. 文案与交互偏好（本用户已拍板，不要回退）

- 按钮文案字数对仗：`保存本地` / `分享上屏`（4字对4字）。
- 保存 = 点击直接 toast「已保存」，**不做长按弹层效果**（原型不浪费时间做效果）。
- 画风差异 = 简单 CSS filter 示意（水墨=grayscale+sepia、手绘=低饱和、光影=提亮），不做真图。
- 分享/提交等传播关键按钮不能沉底（一屏看不到容易遗漏）——与保存并列主按钮。
- 全程界面不出现"AI / 智能"字眼。
