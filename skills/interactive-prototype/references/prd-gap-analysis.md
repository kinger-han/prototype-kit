# PRD 差距分析参考（大批量变更前置）

> 本文件配合 `interactive-prototype` skill 的"Phase 0: PRD 差距分析"章节使用。
> 当用户已有 PRD + 原型，并补充大量变更需求时，按此流程执行。

---

## 触发条件

- 用户贴 PRD/README 文件 + 大段补充信息
- 补充信息中包含"先不用改，记录下来" / "有矛盾列出来" / "等梳理好完整方案再对照原型"
- 变更涉及 3+ 个页面或 10+ 个改动点

## 输出物清单（按顺序）

### 1. 矛盾冲突清单

格式：
```
| # | 冲突点 | 补充信息要求 | PRD/README现状 | 需你决断 |
|---|--------|-------------|---------------|----------|
| C1 | ... | ... | ... | ... |
```

每条矛盾必须包含：
- **冲突点**：一句话描述什么在矛盾
- **补充要求**：用户补充信息中要求什么
- **PRD现状**：现有文档/原型是什么
- **需决断**：具体问用户要选哪个方案

### 2. 不清楚/待确认清单

格式：
```
| # | 问题 | 影响范围 | 备注 |
|---|------|---------|------|
| Q1 | ... | ... | ... |
```

与矛盾冲突的区别：矛盾是"补充信息 vs 现有文档"的冲突；待确认是"补充信息自身不明确或信息不足"。

### 3. 统一 PRD（决断后产出）

整合所有决策后的完整 PRD：
- 按"模块/页面"组织，不按"补充信息条目"组织
- 每个模块含：页面布局、字段表、交互规则、数据联动
- 新增/变更的规则用**加粗**标注，保留不变的不重复写

### 4. 原型修改清单 + 风险评估

格式：
```
| # | 改动项 | 现状 | 目标 | 改动量 | 风险 |
|---|--------|------|------|--------|------|
| R1 | ... | ... | ... | 小/中/大 | 🟢/🟡/🔴 |
```

按页面分组：全局/菜单 → 资源管理页 → 详情页 → 编辑页 → 审核页 → 上传弹窗 → 新建页面

### 5. 风险汇总与 Phase 划分

```
Phase 1 — 菜单+低风险改动（先跑通骨架）
Phase 2 — 核心交互改动
Phase 3 — 大改造（标签体系/审核页重构/新组件）
Phase 4 — 新页面
```

## 设计方案输出规范

当用户要求"你来设计"某个功能/交互时：
1. **先拆解问题**：说明核心矛盾是什么
2. **给出推荐方案**：带表格/示意图的结构化描述
3. **说明好处**：为什么这样设计
4. **放在统一 PRD 中**，不单独输出

示例（标签必填逻辑设计）：
```
核心矛盾：必填粒度太粗（整棵树必填）无意义，太细（每叶子必填）负担重
推荐方案：分组级必填
| 层级 | 能否设必填 | 说明 |
|------|-----------|------|
| 一级节点 | ✅ | 管理员勾选 |
| 二级及下 | ❌ | 只挂标签 |
校验逻辑：必填的一级分组下至少选一个子节点
```

## 踩坑记录

### 「待确认」标记的使用（2026-08-05）

用户补充信息中自带"待确认"段落时：
- 如果补充信息正文已给出方向（如"可挂在任意层级节点"），**按正文方向处理**
- 在统一 PRD 的"待后续确认项"中保留标记（D 编号），注明"暂时允许，后续再确认"
- 不要因为"待确认"标签就停止推进，也不要矛盾地既按正文处理又在待确认中质疑同一个点

### 矛盾冲突 vs 不清楚的判定

- 补充信息**自身矛盾**（正文说A，待确认问A）→ 归为矛盾冲突（C），让用户决断
- 补充信息**与PRD冲突** → 归为矛盾冲突（C）
- 补充信息**信息不足**（如"你来设计""考虑一下"） → 归为待确认（Q），给方案后用户确认

### 原型比对阶段的读取策略

对照现有原型出修改清单时：
1. 先读 `proto-config.json`（菜单结构）和共享数据页的 `renderAppSidebar`（菜单渲染逻辑）
2. 读目标页面的 PAGE_META（第1行）+ HTML结构 + JS关键函数
3. 不需要通读全部源文件——只读与改动相关的函数和DOM结构
4. 用 grep 定位共享数据（如 `TAG_GROUPS`、`CATEGORY_TREE`）定义在哪个文件

### 执行交接时的风险标注

修改清单中的 🔴 高风险项在交接给 Claude Code/Codex 时应特别标注：
- 标签弹窗数据结构变更（扁平→多级树）：需重写 HTML + JS + 数据结构
- 新组件（如右侧抽屉）：需新建 DOM + CSS + JS，注意 z-index 和动画
- 页面重构（如审核页行式→表格）：影响现有交互逻辑，需回归测试
