# 详情页/编辑页布局与返回机制（B 端资源类页面）

> 来源：智融平台-主题管理 V4.16-V4.17（2026-08-10/11），用户多轮反馈收敛。
> 适用：资源/内容的「详情页 + 编辑页」类页面，含预览图 + 表单/信息区。

## 一、返回按钮必须回来源视图（用户交互硬要求）

**场景**：列表页有多种视图（主题列表 / 资源卡片 / 主题内资源），点「查看/编辑」进详情/编辑页，
返回按钮应回到**点进来时的那个视图**，不能重置成默认视图。

**失败模式**：来源页 `init_xxx()` 每次进入都强制重置视图状态（如 `RES_MGMT_VIEW='topic'`），
从卡片视图进详情再返回 → 回到主题列表 → 用户反馈"不能全部默认都回到主题列表"。

**正确做法（RES_VIEW_RESTORE 标记模式）**：
1. 跳转函数记录来源 + 置恢复标记：
```js
function openResDetail(id) {
  RES_CURRENT_ID = id;
  RES_BACK_PAGE = RES_CURRENT_PAGE;   // 记录来源页
  RES_VIEW_RESTORE = true;            // 标记：返回时需恢复视图
  protoShowPage('resource-detail');
}
```
2. 来源页 init 里：仅首次进入才重置视图，返回时不重置：
```js
if (!(RES_VIEW_RESTORE && RES_BACK_PAGE === 'resource-mgmt')) {
  RES_MGMT_VIEW = 'topic';            // 只有真正新进入才重置
  RES_MGMT_TOPIC_RES_VIEW = null;
}
RES_VIEW_RESTORE = false;             // 用后即清，避免误恢复
```
3. init 末尾按当前视图状态重渲染显隐（tbl/cards/viewBtn 的 display），
   并覆盖「主题内资源模式」（backBar 显示、viewBtn 隐藏）。

**配套**：详情/编辑页 `renderAppSidebar()` 高亮判断要覆盖所有来源页 id
（`RES_BACK_PAGE === 'resource-mgmt' ? 'resource-mgmt' : ...`），
否则从公共资源进详情侧边栏高亮错位。

## 二、详情页布局：竖版左图右信息连续排布、横版上图下信息

用户痛点：竖版详情「基础信息下方、审核流程/操作记录之间是空的」；横版「有空内容区域」。

**竖版（9:16）**：左预览图（320px）+ 右侧**连续**信息卡（基础信息 → 资源标签 → 审核流程 → 操作记录）。
关键：不要底部三列独立成行（det-bottom 在 det-main 外 → 中间留白）；全部放 det-right 内纵向堆叠。

**横版（16:9）**：预览图全宽限高居中（max-width:640px），文件信息条横排；
下方信息区改 3 列 grid（基础信息整行 + 标签/审核/操作记录三列）：
```css
.det-main.h-mode { flex-direction: column; }
.det-main.h-mode .det-preview-panel { width: 100%; }
.det-main.h-mode .det-thumb-wrap.h { max-width: 640px; margin: 0 auto; }
.det-main.h-mode .det-right { display: grid; grid-template-columns: 1fr 1fr 1fr; gap: 14px; }
.det-main.h-mode .det-right > .det-card:first-child { grid-column: 1 / -1; }  /* 基础信息整行 */
```

**顶部不放字段**：标题 / 所属主题·路径 / 状态徽章行全部并入「基础信息」——标题 →「资源名称」；「路径」与「所属类别」是同一字段只留一个；平台徽章（`广电昊象·待审核` / `东方有线 · 未同步`）作为「同步平台」字段的值；审核状态成为基础信息一格。顶栏只留「返回 + 操作按钮」。

平台「未同步」不能显示孤立 `/`（"待校对 /"比例失衡），显示 `平台名 · 未同步`。

## 三、图下信息：横竖版共用一条，不做两套

**不要给横版单独写一个「文件信息盒」。** 曾经的做法是横版多一个 `.det-file-info-box` 列 6 行（文件名称/格式/分辨率/大小/上传时间/创建人）、竖版隐藏它——结果是同一份数据两套渲染，两种方向下字段名与位置还对不上。用户最终口径：

- 两种方向共用**一条**图下信息条：`分辨率 / 格式 / 大小 / 创建人 / 创建时间`
- **「文件名称」不要出现在这里**——资源名进「基础信息」（详情页叫「资源名称」），否则与标题重复
- 详情页与编辑页用**同一套字段、同一位置**（`.det-file-strip` / `.edt-file-strip` 同结构）
- 横版只保留比例差异：
```css
.edt-main.v-mode .edt-thumb-wrap { aspect-ratio: 9 / 16; }
```

**JS 切换**：init 里按 `r.direction` 给容器加 class（现仅用于控制宽度与比例）：
```js
edtMain.classList.toggle('h-mode', r.direction === '横版');
edtMain.classList.toggle('v-mode', r.direction !== '横版');
```

## 四、查看页 / 编辑页字段顺序逐行对齐（用户硬要求）

用户口径：字段的顺序位置，查看和编辑尽量在同一个位置，点编辑后字段位置和显示状态不要相差太大。

- **两页字段顺序必须逐行一致**，改其中一页就要同时改另一页。可用序列：`资源名称` → `资源类型·资源方向` → `所属主题·同步平台` → `上架状态·(审核状态|占位)` → `轮播时长` → 方向专属块 → `备注`
- **只读字段用只读文本展示，不要用 `disabled` 下拉**：disabled 会变灰、位置与查看页差距大，正好违背上一条。换成 `<span class="edt-readonly" id="editXxxText">`，init 填 `textContent`，保存时**不写回**（值来自资源本身）
- **只读字段去掉必填标识**：没有校验的字段不该带 `req` 星号；剩下的必填项应当就是真需要用户填的那几个（名称 / 轮播时长 / 标签）
- **可选集合字段用多选 chip 并允许为空**，不要用带「无」选项的单选下拉。读写用一个 `toggle` 函数 + `renderXxxChips(names)` 回填
- **同一信息一页只出现一次**：顶部标题/副标题与字段区重复时只保留字段区一处。用户会逐条抓重复（标题 vs「资源名称」、「路径」vs「所属类别」、「所属主题」出现两遍）
- **状态徽章一个维度一个**：两个状态含义重叠时合并成一个，不并排堆（如卡片上的「上架状态」胶囊并入审核状态展示，上下架仍在「更多」菜单里操作）
- **两页读数同源**：详情页与编辑页的同一字段（平台、时长、图下元信息）都从同一个共享取值函数读（如 `resPlatformsOf(rid)`），别让两页各自算一遍——否则会出现「详情显示两个平台、编辑页一个都没选中」
- **两页字段集合不同时，编辑页字段必须是详情页字段的「子序列」**：详情页多出的展示型字段（审核状态 / 视频背景图 / 关联需求）在编辑页整格去掉，编辑页多出的可改文件字段（资源替换）落在详情页「视频背景图」那一格的位置上——**被删的位置留空，不把后面的字段往前挤**，否则点「编辑」后每个字段都跳了半格
- **⚠️ 占位宽度按用户最新口径，别把「长文本字段独占整行」固化成规则**：同一批字段，用户先要求「资源名称/主题/分类可能很长 → 独立整行」，看过真实渲染后又改口「除备注、文件类字段外全部双列」。当前口径：基础信息一律**双列**，只有**备注**和**文件/资源替换类字段**（要放缩略图 + 按钮）整行。改这类布局前先确认口径有没有被推翻，不要沿用上一轮的排版结论
- **文件/资源类字段用「小缩略图 + 一个上传按钮」，不做文件名清单**：用户明确否掉了「图标 + 文件名 + 大小 + 删除」的 Upload 列表形态，要的是 60×60 缩略图 + 单个「上传资源」。视频类资源再加一个「视频背景」字段（仅视频类资源显示），同样是纯缩略图。文件名、大小、删除入口一律不给

## 五、状态切换类字段：编辑页不承载，改用详情页操作按钮

**最终口径（覆盖早期的 Switch / 单选组方案）**：
- 同一字段被改过三轮：编辑页 Switch（用户反馈"上架状态点击切换太不合理"）→ 单选组（上架/下架）→ 用户直接要求**编辑页整块去掉该字段**。三轮都不是终态，**终态是「编辑页根本没有上架状态」**
- 判据：**能改但属于「操作」而非「编辑」的状态**（上下架、启停、发布）由**详情页/列表页的操作按钮**承载。塞进编辑表单 → 同一状态两个入口、两套权限、两套审核判断
- 编辑页只留三类字段：可改的业务字段（名称/标签/时长/备注）、只读的归属字段（分类/类型/方向/主题/平台）、文件类字段。**状态与审核状态一律不进**

**状态按钮的文案与审核差异**（两个方向的审核要求常不对称，动手前先问清）：
- 文案写**下一步动作**、随当前状态切换：已上架 → 显示「下架」；已下架 → 显示「上架」。不要写成一个固定的「上架/下架」双态词
- 免审方向**直接生效**（下架 = 改数据 + 立即 toast）；需审方向**二次确认**（重新上架 = 弹确认框写明"需重新走审核流程"，确认后 toast"已提交上架审核"）

**布尔字段在卡片/列表里原地切换**时仍用 AntD Switch 样式（只切 class + 文案，不重渲染列表）：
```css
.edt-switch { position: relative; width: 44px; height: 22px; background: rgba(0,0,0,.25);
  border-radius: 22px; cursor: pointer; transition: background .2s; }
.edt-switch::after { content:''; position:absolute; top:2px; left:2px; width:18px; height:18px;
  background:#fff; border-radius:50%; box-shadow:0 2px 4px rgba(0,0,0,.2); transition: left .2s; }
.edt-switch.on { background:#1677ff; }
.edt-switch.on::after { left: 24px; }
```
旁边显示状态文字 label；JS 只切 class + 文案，不重渲染。

## 六、编辑页的保存与「改动触发审核」（轻方案）

用户明确否决了字段级方案——「每个字段标一份『是否触发审核』的元数据、前后端各维护一份」被判为"实现麻烦，后面改字段的时候也麻烦，需要前后端一起处理"。
**采用的做法：进页面快照 + 保存时比对 + 白名单命中则二次确认**

1. 进编辑页时对**需审核字段**取快照：`RES_EDIT_SNAPSHOT = { title: r.title, tags: [...] }`
2. 点「保存修改」时逐项比对，收集命中项（如 `资源名称` / `资源标签` / `资源替换`）
3. **命中 → 弹通用确认框**，正文列出命中的字段名 + 提示"保存后该资源将重新提交审核"，确认后才落库并 toast"保存成功，已重新提交审核"
4. **未命中 → 直接保存**，toast"保存成功"，不动审核状态
5. 需审白名单与免审字段分开维护（本例：备注 / 轮播时长免审；名称 / 标签 / 文件替换需审）。用户口径是"先按这个来，后面需要时再更新"，所以白名单要写成一眼能改的形式，不要散在逻辑里

配套两条：
- **编辑页全局只留一个「保存修改」，放顶栏右上角**（与「返回」同一行）。页面内部的取消/保存按钮全部删掉——两个位置两套按钮，用户不知道哪个才是真提交
- 编辑页底部保留一条常驻说明「修改将重新提交审核」。它与保存时的确认框不冲突：**常驻说明讲规则，确认框讲本次命中了哪些字段**

## 七、详情页操作按钮：排序与增删判据

**排序按「使用链」，不随意罗列**：`内容 → 状态 → 分发 → 销毁`。本例最终序：
`编辑` → `审核` → `上架/下架` → `一键上屏` → `删除`
- 最高频的（编辑）贴最左、靠内容区
- **不可逆操作（删除）永远放最右、单独红色描边**，与常用键拉开距离
- 交付报告里把这个排序理由一并说明（用户会问"为什么这么排"）

**按钮增删的两条相反判据，别混**：
- **功能系统里已有 / 将来会有 → 保留按钮，点击给 toast**（下游页面原型不做）：如「一键上屏」——上屏页系统已有，点按钮 `resToast('已一键上屏')` 即可
- **能力产品上不允许 → 直接删按钮，不留「开发中」占位**：如资源不允许下载，就把「下载」按钮连同 `resToast('下载功能开发中')` 一起删掉。留一个点了弹「开发中」的按钮，等于承认产品有这条能力
- 按钮改名要与系统里的既有叫法对齐（弹窗标题早已叫"一键上屏"→ 按钮也统一叫「一键上屏」），动手前 grep 项目里有没有该说法的既有出处

## 八、验证清单

- 三个入口各测一次：卡片视图 → 详情/编辑 → 返回（应回卡片）；主题列表 → 返回（应回列表）；主题内资源 → 返回（应回该主题资源）
- 竖版/横版资源各开一次详情+编辑，确认无空区、图片比例正常
- **字段顺序对齐**：同一条资源先开详情、再开编辑，逐行比对两页字段顺序与位置
- **两页同值**：图下信息条、同步平台在详情与编辑页显示的值必须一致（同源取值函数生效）
- **删字段后扫孤儿 id**：跑 `scripts/find-missing-element-ids.py <项目目录>`，再遍历全部页面收运行时错误（`window.__errs` 必须为空）。被删元素常被**别的功能**引用——删掉编辑页主题下拉后，标签选择弹窗读 `editTheme` 取主题名会抛 null，整段 init 中断
- `grep -c "RES_VIEW_RESTORE" dist` 确认机制注入
- **两页字段集合差异**：详情页比编辑页多出的字段位置是否留空（编辑页字段没有整体前移）
- **按钮增删落地**：被删掉的能力（如下载）在项目里 grep 归零；新按钮文案与系统既有叫法一致（grep 对照）
- **保存两条分支各走一遍**：只改免审字段（备注/时长）→ 直接保存；改需审字段（名称/标签/文件）→ 弹确认框且列出命中字段名
- **状态按钮两个方向各走一遍**：免审方向立即生效 + toast；需审方向弹确认后 toast
