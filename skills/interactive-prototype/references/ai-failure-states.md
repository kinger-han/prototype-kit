# AI 生成功能的失败态设计规范

适用：任何调模型 / 长耗时生成的功能（风格化、海报生成、图像编辑……）在移动端对用户暴露失败时的口径。
场景约束：政务 / 现场活动，用户年纪偏大、停留时间短、无法理解技术描述。

---

## 0. 三条铁律（先看这个）

1. **失败是状态，不是按钮。** 界面上它是状态文字（红系、无边框），不做成描边按钮——做成按钮，用户会理解成「点我重试」。
2. **重试必须显式且独立。** 单独一条文字链（「重新生成」），禁止点击状态本身或整行隐式触发重试——那样用户没有说「不」的机会。
3. **必须留「我不要了」的出路。** 失败后用户有权放弃；失败信息**绝不常驻**。

配套判据：**需要用户决策的次级事项不要做成一整张模态卡**（「重新生成 / 放弃」摊平到行内即可）。反过来看——模态里若需要「暂不处理」这类选项，本身就证明这次打断不必要。

---

## 1. 铁律：用户界面永不出现技术信息

禁止出现在 UI 的：模型名（GPT Image / gpt-image-2 …）、HTTP 状态码、接口路径、英文 error message、堆栈、request id。

**最容易漏的一道**：原始错误被写进了**会被直接渲染的字段**（作品名 / 标题 / 卡片主文字），列表行就变成一串报错。

- 名称类字段**只能**来自本地字典（风格名 / 模板名），任何情况下不被 error 占用。
- 再加一道渲染层兜底：名称字符串命中 `HTTP|Error|Exception|失败：` 等模式 → 回落到字典名。
- 错误详情只进日志与 B 端台账，不进用户端。

---

## 2. 失败分类（决定说什么）

| 失败原因 | 用户能否自救 | 该说的话 |
|---|---|---|
| 网络中断 / 超时 | 能，重试即可 | 网络不太稳定，请再试一次 |
| 生成服务故障（超时、5xx、模型报错） | 不能，但可重试 | 生成没有完成，请稍后再试（**不提后台**） |
| 内容安全未通过 | 换风格可能可行 | 这张照片暂时没法生成，可以换个风格试试 |
| 素材本身不合规（无人脸等） | 需换素材 | 没识别到人脸，建议重新拍一张 |
| 次数用尽 | 不能 | 今天的生成次数用完了 |

**统一原则**：所有失败收敛到**同一套行内表现**（状态词 + 显式重试入口），不因底层原因变来变去——文案分支越少，用户越不容易困惑，实现也越稳。

---

## 3. 文案三段式（行内承载，不弹卡）

```
发生了什么（用户视角）
→ 有没有影响（不会保存到你的作品 / 原图还在）
→ 怎么办（重新生成 / 放弃）
```

给确定感，而不是让用户猜「我的照片是不是没了」。三句**各自落在已有的行内元素上**：

- 「发生了什么」→ 右侧状态词（如「生成失败」）
- 「有没有影响」→ 副文字短句（如「生成没有完成」）
- 「怎么办」→ 行内文字链（如「重新生成」）

**不要为了塞下这三句而弹一张卡。**

---

## 4. 各入口的表现（无模态卡版本）

| 入口 | 显示 | 交互 |
|---|---|---|
| 任务列表（如「风格照生成」区）的失败行 | 缩略图保持该风格滤镜示意；主文字 = 名称字典值；副文字 = 短句「生成没有完成」；右侧状态「生成失败」（红系文字/胶囊） | 行内文字链「重新生成」——**不整行触发重试** |
| 选择弹层（如「更多风格」）的失败项 | 该项显示状态「生成失败」（不可点、非按钮样式）；弹层内不出现任何错误详情 | 该项右侧文字链「重新生成」 |
| 失败信息的生命周期 | 不常驻、不跨会话（退出重进即清）；或行尾小 × 主动划掉 | 放弃后该项回到「未生成」，以后想试还能试 |

约定：**失败作品不进作品列表**，只出现在任务区，放弃后消失。

---

## 5. 前后端约定

- 后端失败时**不下发原始 error message**，只回 `status: failed` + `fail_code` 枚举（如 `network / gen_error / safety / limit`）；堆栈与厂商报错只进日志。
- 前端按 `fail_code` → 本地文案字典映射；字典缺失时回落到通用句「生成没有完成，请稍后再试」。
- 埋点带 `fail_code` + 耗时，便于后端定位，不占用用户界面。
- 原型阶段：用数据打标触发失败（如风格项 `demoFail: true` → 该风格必失败），走正常路径即可演示失败链路，不依赖演示菜单。
